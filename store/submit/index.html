把你的插件放上来

第三方作者也能投稿 —— 走 GitHub 表单，不用会 git；审核通过后上架 web 仓库的 插件商店，应用内「插件市场」就能装。

打开投稿表单 插件开发指南

怎么投稿

三步：填表单 → 维护者打包上架 → 应用里能装。源码放在 web 仓库的 plugins/<id>/， 打包产物放在 store/packages/<id>-<版本>.zip，索引就是 store/index.json。

① 填投稿表单

  • 点上面的按钮打开 GitHub 投稿表单（需要一个 GitHub 账号）
  • 填插件 id、显示名、版本、依赖，以及授权方式与源码地址
  • 再贴一个zip 下载地址：先传到自己的网盘或 Release，别把 zip 贴在 issue 里

② 插件怎么打包

  • 插件 = 一个目录 + 一份 manifest.json；宿主不认识任何具体插件，加功能不用碰主程序
  • 清单里显式写 id（它就是身份），并声明自己占用哪些 API 前缀与静态地址
  • zip 的根目录直接是文件（不要把整个插件目录再套一层）

③ 上架后会怎样

  • 维护者把 zip 放进 store/packages/，并在 store/index.json 登记一条
  • 应用里 设置 → 插件 → ✦ 插件市场 立刻能看到，点安装即用
  • 插件默认关闭，装完要自己打开开关 —— 它改动界面，不该在你不知情时生效

站点是 GitHub Pages 静态托管，没有服务端接收文件，所以做不了「网页里选个文件直接上传」—— 通道就是上面的表单。要做到网页直传，得另起一个小后端（GitHub App / Worker 代提交）， 代价是多维护一个服务与一份凭据，暂不做。

投稿前请确认：代码与资源你有权分发（或已获授权），并愿意公开源码地址。 安装插件 = 信任它的代码（它在页面同源环境里运行），所以上架会看源码； 另外手机（APK）上没有服务端，声明了 server 那半边的功能要能在缺失时降级。
