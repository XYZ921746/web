插件投稿

把你的插件放上来

第三方作者也能投稿 —— fork 本仓库、加插件、发 PR，合并即上架 web 仓库的 插件商店，应用内「插件市场」就能装。源码进仓库 = 自动「已审核」（普通列表 + 绿色角标）； 只提交 release 下载地址 = 「第三方插件（未审核）」分区（客户端自动显示未审核警告）。

投稿指南（README） 开发文档
  • fork + PR
  • 合并即上架
  • 第三方分区

怎么投稿

三步：fork → 加插件发 PR → 合并即上架。源码放在本仓库的 plugins/<id>/， 索引是 store/index.json，打包产物在 store/packages/<id>-<版本>.zip（维护者打包）。完整步骤与字段说明见仓库 README 投稿指南。

① 填投稿表单

  • Fork 本仓库，从 main 建分支；插件源码放进 plugins/<id>/（id 与 manifest.json 一致）
  • 在 store/index.json 登记一条；社区投稿必须标 thirdParty: true，源码投稿再标 reviewed: true（合并即「已审核」，进普通列表）
  • 发 PR：模板自带检查单，写清授权方式与源码地址，合并即上架

② 插件怎么打包

  • 插件 = 一个目录 + 一份 manifest.json；宿主不认识任何具体插件，加功能不用碰主程序
  • 清单里显式写 id（它就是身份），并声明自己占用哪些 API 前缀与静态地址
  • zip 的根目录直接是文件（不要把整个插件目录再套一层）

③ 上架后会怎样

  • 维护者合并 PR 后打包放进 store/packages/，Pages 自动重新发布
  • 源码投稿：应用里普通列表可见，卡片带「第三方·已审核」角标；只交 release 地址：进「第三方插件（未审核）」分区
  • 未审核分区未经审核：卡片带「未审核」角标，安装即信任其代码与其注册的 AI 工具

投稿通道是 fork + PR（原 GitHub 表单通道已下线）。审核分级与投稿方式绑定： 源码 PR 进仓库 = 自动「第三方·已审核」；只交 release 下载地址 = 「第三方·未审核」—— 请谨慎下载使用。未审核的插件随时可以补交源码转已审核（发一个源码 PR 即可）。

投稿前请确认：代码与资源你有权分发（或已获授权），并愿意公开源码地址。 安装插件 = 信任它的代码（它在页面同源环境里运行），所以上架会看源码； 另外手机端的内嵌服务是否随包分发取决于构建开关，声明了 server 那半边的功能要能在服务缺失时降级。
