为什么是「Mod 优先」

大多数聊天应用把花哨功能焊死在主程序里 —— 你不用也得装着，卸不掉，坏了还会拖垮整个应用。这里的取舍相反。

清单驱动

加载器只认 manifest.json，不硬编码任何插件名。新增功能 = 加一个目录，不用碰主程序。

失败隔离

插件的加载与初始化都包在 try/catch 里，一个坏插件只会被标记出错，其余照常运行。

资源与代码分离

立绘、背景图这类公共资源被多个界面共用；卸载某个界面不会把公共资源一起带走。

BYOK 直连

请求从你的设备直接发给服务商。没有作者网关、没有共享套餐、没有内置密钥。

模型投稿

第三方作者也可以把自己做的模型放上来。走 GitHub 表单，不用会 git；审核通过后作为 web 仓库的 Release 资源上架，并登记进上面的列表。

① 填投稿表单

  • 点下面的按钮打开 GitHub 投稿表单（需要一个 GitHub 账号）
  • 填模型名、作者、授权方式，以及模型 zip 的下载地址
  • 模型动辄几 MB，别直接贴在 issue 里：先传到自己的网盘或 Release，贴链接就行
打开投稿表单

② 模型怎么打包

  • zip 的根目录就是模型名那一层（解压出来是「模型名/…」，不是一堆散文件）
  • 必须含 .model3.json + .moc3（Cubism 3）与纹理图
  • 中文名、空格都支持；放一张 icon.png 就有缩略图，没有就显示名字首字

③ 为什么不能直接传文件

站点是 GitHub Pages 静态托管，没有服务端接收文件，所以做不了「网页里选个文件直接上传」。 现在的通道是：表单投稿 → 维护者把 zip 传到 Release → 登记进模型区。 要做网页直传，得另起一个小后端（GitHub App / Worker 代提交），代价是多维护一个服务与一份凭据，暂不做。

模型是二进制：按项目惯例不进 git 历史（改一次就多存一整份），一律走 Release 分发 —— 这也是投稿先交下载地址、而不是直接塞进仓库的原因。模型素材的著作权属于各自作者。

电脑版 / 安卓版

聊天与界面两端同构，但「能操作什么」是互补的。

电脑版（Web）

  • 克隆仓库，双击 启动.bat（零依赖、零构建，需 Node.js ≥ 20）
  • 浏览器打开 http://127.0.0.1:4173
  • Agent 可读写电脑文件、执行本机命令

安卓版（APK）

  • 到 Releases 下载 lite-debug.apk（约 10.8 MB）
  • 允许「安装未知来源应用」后安装
  • Agent 可操作手机：点击 / 滑动 / 输入 / 截图 / 读通知

APK 是「纯净版」——只含程序本体，不含任何插件与图片资源；那些按需下载并在应用内安装。
